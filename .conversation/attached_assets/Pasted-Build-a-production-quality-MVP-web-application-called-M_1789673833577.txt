Build a production-quality MVP web application called MEKRIVO.

MEKRIVO is a destination-aware file readiness platform.

Core idea:

A user has a file and needs to upload it somewhere, but the destination has requirements such as file type, maximum file size, dimensions, page count, aspect ratio, filename rules, encryption restrictions, or other technical constraints.

MEKRIVO should help the user:

1. Upload a file.
2. Tell MEKRIVO where the file is going, either by:
    * entering a destination name,
    * entering a URL,
    * or selecting a predefined destination.
3. Determine the technical requirements for that destination.
4. Analyze the uploaded file against those requirements.
5. Clearly show what passes and what fails.
6. Automatically fix mechanical problems where possible.
7. Re-check the resulting file.
8. Show a final READY / PASS state.

IMPORTANT PRODUCT PRINCIPLE:

Do NOT build this as another generic PDF toolbox.

The primary experience must always be:

FILE → REQUIREMENTS → CHECK → FIX → VERIFY → READY

Generic file tools can exist, but they are secondary.

* source

Create a reusable rule engine.

Example conceptual rule:

{
type: “maxFileSize”,
value: 5000000,
unit: “bytes”
}

Other examples:

{
type: “allowedExtension”,
values: [“pdf”]
}

{
type: “maxPages”,
value: 10
}

{
type: “imageDimensions”,
maxWidth: 2000,
maxHeight: 2000
}

The engine should produce results like:

PASS
FAIL
WARNING
UNKNOWN

Every check should return:

* rule
* actual value

* status
* human-readable explanation
* whether MEKRIVO can automatically fix it

FIX ENGINE

Create a Fix Engine with a clean abstraction.

The Fix Engine should know which failures are automatically fixable.

MVP fixes:

PDF:

* compress PDF
* remove metadata where safe
* rotate pages
* reorder pages
* remove pages
* merge PDFs
* split PDF

Images:

* resize
* compress
* convert JPG/PNG/WEBP
* change dimensions
* change quality

Documents:

* DOCX → PDF where technically possible

Every fix must return a new file and never destroy the original.

==================================================
VERIFY AFTER FIX

This is critical.

Never simply tell the user that a fix succeeded.

After every automatic fix:

1. Generate output file.
2. Analyze output again.
3. Run the requirement engine again.
4. Confirm whether every required rule passes.

Only show:

READY

when the verification actually passes.

Example:

↓

↓
✓ File type
✓ File size
✓ Dimensions
✓ Pages
✓ Filename

MEKRIVO
